# 小说改编短剧 · Narratica 运行子集

> 来源：`z7ping/novel-agent-skills@98ea528ac8754d2af4eef23f2491602ce2afc2a3` 的 `screenplay/skills/00-novel-to-short-drama/SKILL.md`。本文件是 Narratica 随包运行子集，只保留当前已实现能力和安全边界；完整方法继续以上游 Skill 仓库为准。

## 目标

把当前作品中已经正式确认的小说内容推进为可继续生产的短剧剧本，同时保持：

- 小说正式事实不被改编流程反向修改；
- 来源范围、改编方案、剧本工作稿与正式剧本分层；
- 所有待确认内容继续保持待确认；
- 作者明确确认前，绝不宣称“已定稿”“已采用”或“已进入正式生产”。

## 开始前

1. 先读取当前项目的改编来源状态、改编方案和剧集状态。
2. 只把已经正式确认且版本仍有效的小说正文当作改编输入。
3. 如果上游版本已变化，先说明旧改编结果已过期，再生成新的待确认内容。
4. 不要通过 Shell、文件工具或其他旁路直接修改 Story Repository。

## 阶段

### 1. 选择来源

- 读取可用正式小说正文。
- 根据作者意图提出改编范围。
- 可以保存“待确认改编范围”。
- **不能确认改编范围**；需要作者在“选择来源”工作台明确确认。

### 2. 改编方案

方案至少说明：

- 必须保留的故事事实和因果；
- 哪些内容压缩、合并、重排或外化；
- 计划如何分集；
- 关键跨集连续状态；
- 哪些信息必须保持原有呈现媒介，例如终端文字、短信、电话、广播或画外音。

方案保存为待确认稿。**不能由导演自行确认方案。**

### 3. 剧本工作稿

写作时遵守：

- 改编不是逐句搬运小说；
- 心理与叙述优先外化为行动、反应、对白、界面反馈或必要旁白；
- 章节不等于剧集；
- 同一连续场景跨集时，人物、空间、道具、时间和信息状态必须承接；
- 不提前写景别、运镜、供应商提示词或媒体参数。

只能创建或更新 `episode-xxx.proposed.md`。正式剧本必须经过剧本审查和作者确认。

### 4. 剧本审查

审查关注：

- 来源事实和知识边界；
- 戏剧冲突、转折、集尾落点；
- 对白是否承担动作和信息，而不是重复解释；
- 跨集连续性；
- 基本可拍性；
- 是否仍有阻断问题。

可以写入绑定当前剧本版本的审查证据，但**不能执行剧本定稿**。作者必须在“剧本审查”工作台明确确认。

## 确认边界

以下动作都是确定性状态命令，不属于本 Skill 权限：

- 确认改编范围；
- 确认改编方案；
- 剧本定稿；
- 采用视觉资产；
- 确认分镜。

用户在对话中说“这版可以”“定稿”“确认”时，应提醒其到当前对应工作台执行明确确认，不要自行调用任何绕过确认边界的能力。

## 交接

当某集剧本已经正式定稿后，视觉资产、分镜与生产就绪交给 `short-drama-director`。本 Skill 不生成分镜和媒体。

## 输出语言

作者可见内容默认使用中文；只有中文无法准确表达时才使用“中文（English）”。
