# book-decomposition

## 分类
马良原生知识库功能（native）。README 对拆书来源、维度、异步批量任务和个人知识库有详细说明。

## 来源
- `text`：用户直接给文本。
- `file`：TXT/Markdown 等可读取文本。
- `url`：宿主有合法网页获取能力时读取；马良 README 特别说明番茄 URL 依赖第三方小说内容获取服务。

无法读取 URL 时必须要求用户提供文本，不伪造分析。

## 可选分析维度
按材料和任务选择，不要求每次全做：
1. 文风叙事：叙事方式、节奏、视角、句式层面的高层特征。
2. 情节设计：核心冲突、悬念、节奏、推进模式。
3. 人物塑造：角色功能、欲望、关系、成长方式。
4. 世界/特色：世界观、金手指、力量/成长体系。
5. 读者情绪：共鸣、爽点、嗨点、期待管理。
6. 热梗搞笑：幽默机制、网络文化使用方式。
7. 章节大纲：章节功能与情节发展脉络。

### 派生分析（非马良 README 原生维度）
如果用户明确要求，可以基于“章节大纲”结果进一步分析开篇/黄金三章分别承担什么功能；这一项属于本项目二次分析，不得标成马良原生拆书维度。

## 分批处理
长文本按章节/区段拆分，再按维度汇总；不要单次把全文塞给模型。不同维度可以并行或分组执行，失败项可单独重试。

## 知识卡契约
```yaml
---
type: knowledge
status: reference
source: decomposition
work: <source label>
source_ref: <file/url/import-id>
source_hash: <optional>
dimension: <dimension>
---
```
每张卡还应记录能回到原材料的 `source_ref`，必要时用章节号/段落范围作为 evidence anchor；不要靠复制长原文做证据。

正文用：
- 观察到的机制
- 为什么有效
- 适用条件
- 可迁移方式
- 容易翻车的风险

## 版权/风格边界
- 不存大段原文。
- 不把具体章节改名后当模板。
- 不复制标志性对白。
- 用户要“照着某作者/某书写”时，提炼高层特征，不做高度近似复刻。

## 存储
`07-materials/knowledge/<work-id-or-slug>/<dimension>.md`，状态永远是 reference，不是 story canon；作品显示名保存在 frontmatter `work`，避免特殊字符/重名影响路径。

## 与创作联动
只有当前任务或 Preset 明确要求参考某类知识时，`16-context-assembly` 才检索相关知识卡。
