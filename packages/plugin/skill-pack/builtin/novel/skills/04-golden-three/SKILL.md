# golden-three

## 分类
马良原生功能（native）。README 明确描述：快速设定完成并微调后，点击“黄金三章”，生成前三章大纲和摘要。

## 目标
快速建立前三章的可写蓝图，并验证读者是否能在前三章看到主角、冲突、核心卖点和继续阅读理由。

## 前置
必读：
- `01-brief/brief.md` 中已有的核心创意/定位索引。
- 已确认核心设定，尤其主角、核心机制/金手指、初始关系、世界硬规则。
- 当前 Golden Three Preset。

可选读取：
- 若项目已经存在 `03-outline/main.md` 或第一卷纲，把其中与开篇直接相关的约束作为上层限制。

**不得把全书大纲作为 Golden Three 的硬前置。** 马良公开链路是 Quick Start/设定生成与微调后即可进入黄金三章；已有总纲/卷纲只能增强一致性，不能阻断该功能。

缺少非关键信息时标待确认；不要为了凑齐模板强行生成百科式设定。

## 输出
严格以**前三章章节大纲 + planned 摘要**为主，不直接生成三章完整正文。

每章包含：
- 章节标题/定位
- 章节目标
- 开场状态
- 主要事件链（本项目默认 3~5 个；不是马良已验证固定值）
- 核心冲突
- 本章核心信息/卖点兑现
- 本章结果
- 结尾钩子
- `planned_summary`：用于后续扩写的短摘要，必须标 `kind: planned`

## 三章节奏
### 第一章
尽快进入具体处境和冲突；让读者知道“主角是谁、眼下要解决什么”。避免用大量世界观说明代替事件。

### 第二章
让核心卖点、能力、关系或特殊机制真正开始运转，同时制造代价、限制或新的期待。

### 第三章
完成一次可感知的小回报/反转/升级，并抛出比前三章更大的持续目标或威胁。

## 执行流程
1. 先提取前三章共同承担的开篇任务。
2. 设计三章递进而非三个平行介绍章。
3. 检查核心机制是否出现得过早/过晚。
4. 检查每章结尾是否自然驱动下一章。
5. 给出前三章整体评估。
6. 默认先返回 preview/candidate；未确认时写 `06-drafts/golden-three/`。用户确认后才写正式章节蓝图和 planned summary；若目标已有 canonical，仍只生成候选版本，不静默覆盖。用户最终确认替换时先把旧版本归档到 history，历史副本标 `status: archived` + `resolution: superseded`。

## 评估
- 主角辨识度
- 核心冲突是否及时出现
- 核心卖点是否至少兑现一次
- 三章是否递进
- 信息是否过载
- 第三章结束后是否有明确追读理由

## 写入
- 未确认/覆盖候选：`06-drafts/golden-three/`
- 用户确认后的章节蓝图：`03-outline/chapters/chapter-001.md` ~ `chapter-003.md`
- 用户确认后的 planned 摘要：`05-summaries/planned/chapter-001.md` ~ `003.md`，写 `status: canonical`、`scope: chapter`；正文已确认 canonical 且目标 scope 完整后再由 `07-scene-summary` 归档其完成态

这里的“先 candidate、再 canonical”是本项目为 Agent 写文件增加的安全边界；不声称马良 UI 内部使用相同文件状态模型。

## 边界
- 不把 planned 摘要当“正文实际发生摘要”。
- 不自动生成完整三章正文；正文交给 `08-expand`。
- 不为了钩子破坏世界硬规则。
