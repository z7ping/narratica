# polish

## 分类
马良原生功能（native）。README 明确 AI 润色针对“选中文本”的风格、语法、表达优化。

## 输入
- 必须：选中文本。
- 可选：上下文前后各一小段、角色语气要求、文风 Preset、润色强度。

## 默认不可改变
- 人物身份与关系。
- 事件顺序和因果。
- 谁做了什么。
- 谁知道什么。
- 时间、地点。
- 物品/伤势/能力状态。
- 信息揭示节点。
- 场景最终结果。

## 可优化
- 病句、错词、重复。
- 词语准确度。
- 句式与段落节奏。
- 对白自然度与角色差异。
- 动作清晰度。
- 感官描写。
- POV 稳定性。
- 说明性“AI腔”和无效总结。
- 阅读难度、术语密度与抽象概念负担。
- 需要反复回看才能理解的长推理、长句或多层转折。

## 模式
- `light`：纠错、去重复、轻微顺句。
- `standard`：表达、节奏、对白、描写综合优化。
- `readability`：专门降低认知负担。在不改变事实与主题的前提下，把抽象论述改成更直观的动作、例子和人话表达，拆开多层推理，减少术语堆叠，让普通读者正常速度一遍读懂。
- `style:<preset>`：按高层文风特征重塑表达，但事实保持不变。

## Readability 原则
- 目标是“更容易读”，不是“更幼稚”。主题深度、悬念和留白可以保留。
- 先保证读者知道当前人物在做什么、在争什么，再承载更抽象的思想。
- 一个段落尽量承担一个主要理解任务；多个前提、反例、结论挤在一起时拆开。
- 能用具体场景或生活化例子说明时，优先不用抽象名词串联。
- 技术术语若不影响事实准确性，优先换成人话；必须保留时，让含义能从上下文直接读出来。
- 高概念对话中，人物不应突然像论文作者；保留角色口吻、迟疑、误解和现场反应。
- 删除“为了显得深刻”而存在的解释，但不要把必要因果一起删掉。
- 最终检查：普通读者不回看上一屏，是否仍能说清“现在的问题是什么、为什么重要、这一段推进到了哪里”。

## 执行
1. 标出硬事实和不可动信息。
2. 按强度重写。
3. 对照原文检查是否发生事实漂移。
4. 若使用 `readability`，额外检查术语密度、抽象段落长度、推理层数与生活化落点。
5. 返回完整润色选段。
6. 默认 preview；用户确认后只替换选区，并保留旧版或可撤销记录。**编辑目标继承原 authority**：`06-drafts/prose/` 中的 proposed draft 润色后仍保持 `status: proposed` 并更新 draft `updated_at`，不因润色自动提升 canonical；用户随后明确“定稿/作为正式正文”时 handoff 到 `/expand confirm <scene-id>`。
7. 选区来自 `04-scenes/` canonical prose 时，确认替换前保存 safety history，再修改原 canonical scene并更新 `updated_at`。即使润色原则上不改事实，任何 `source_revisions` 包含该 source 旧 revision 的 actual summary 仍因此变 stale；为安全起见下次 Context 不再把旧摘要当 current，直到重做摘要。
8. 选区若来自 `09-imports/chapters/` 的 parsed canonical prose，可以替换该选区；确认替换前保留安全历史，写入后更新 `updated_at` 并标 `source_diverged: true`；`source_revisions` 中仍记录该 source 旧 revision 的 actual summary 随之 stale。`09-imports/source/` 原始导入文件永远不得修改。

## Narratica 宿主适配

Narratica 不允许 Agent 直接原地覆盖 `04-scenes/` 正式正文，因此上面第 7 条在 Narratica 中使用显式重写流程：

1. 先读取目标场景最新状态和正式正文 revision。
2. 调用 Narratica 的“开始重写”能力，把当前正式正文复制成一份**待确认重写工作稿**；原正式正文仍保持当前有效。
3. 本 Skill 只在待确认工作稿中替换用户指定选区，未选中的正文保持不变；修改仍要携带最新 draft/canonical revision。
4. 用户未明确确认前，润色结果不能进入正式正文。
5. 用户明确“这版可以 / 定稿 / 就这样”后，由 Narratica 的确定性确认链替换当前正式版本：旧正式正文归档为 `superseded`，重写工作稿归档为 `promoted`。
6. 正式正文 revision 改变后，引用旧 revision 的 actual summary、一致性检查、质量门禁、章节提交和 Runtime 投影必须视为 stale 或重建；若宿主当前尚未完成对应派生更新，不得声称这些状态已经同步。

这项适配只改变正式正文的安全写入方式，不改变本 Skill “只优化表达、不改变故事事实”的职责。

## 风格边界
用户要求模仿具体在世作者时，转换成可描述的高层特征，如“短句、冷峻、对白克制、少形容词”，不追求高度近似个人独特风格。

## 禁止
润色不是剧情改写。用户要求改变事件时，转 outline / next-outline / expand。
