# ADR-011：故事库目录发现与索引

- 状态：已接受
- 日期：2026-10-25

## 背景

原有 `repositories` 配置把每个路径当作单部作品，并直接读取清单，无法将多作品总目录加入故事库。界面的“打开已有作品”和“接入旧作品”尚未接通；新建作品的内存注册也不能代替持久化目录索引。

## 决策

1. 目录发现由 Stories Host 的 `LibraryDirectories` 负责。总目录和单作品目录使用同一流程，最终仍交给现有 `FilesystemStoryRepository` 和正式清单解析器读取；不建立第二套作品事实源。
2. 用户添加的目录只保存路径，写入 DSH Home 下的 `narratica/library-roots.json`。使用临时文件和原子替换，进程内串行化增删操作；多个 Host 实例同时编辑同一索引尚无协调保证。启动配置与用户目录合并，作品按实际路径和项目标识去重。
3. 故事库刷新时重新发现目录内的作品。标准清单中的领域不限定为小说。损坏、不可访问和冲突项目分别报告，其他作品继续加载；不自动覆盖重复标识的清单。
4. 遍历复用 Node 文件系统能力；不引入通用爬虫。跳过目录链接、隐藏目录、依赖及构建/历史目录；发现作品边界后停止递归。最大深度为 8、目录数为 3000、候选数为 500，元数据文件上限为 1 MiB，截断必须可见。
5. 旧工作区通过 `08-config/project.md` 的 YAML 元数据识别，复用现有依赖树中的 `yaml` 解析。只有作者显式确认后才以独占创建方式新增 `.narratica/project.json`；预览版本过期或项目标识冲突时拒绝写入。
6. 旧格式接入不等于全量迁移。设定会话、快照、正文、规划与候选均保留，不把候选提升为正式事实，也不承诺新版结构化编辑可直接理解所有旧格式。
7. UI 复用故事库的弹窗、表单、卡片、提示及状态样式。目录移除只移除索引，绝不删除作品文件。

## 验证边界

按当前项目约定不运行测试套件。验证包括完整构建、隔离文件系统烟测、真实 `ai-novel` 只读扫描、浏览器添加与移除目录，以及真实服务重启后的目录恢复。旧作品实际清单写入只在隔离样本中验证，用户的《共生纪元》仍等待作者在界面确认。
